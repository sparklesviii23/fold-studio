# RAPID complete engine audit

24 October 2026, Europe/Bucharest. Audit baseline: `b1b489a` and the client submission fixes recorded with this report. **The full engine is incomplete.** Evidence is scoped below; fixture validation, dependency imports, model execution, and biological validation are distinct.

## Actual architectural conclusion

The source implements a **discrete, stateful, multi-model workflow with bounded iterative selection**. It is more than independent launch buttons: one remote coordinator creates immutable candidates, claims stages, checks sequence/coordinate identities, runs separate model branches, assesses fresh predictions, compares objectives, and selects the next frontier. It does **not** implement shared end-to-end differentiation across BindCraft, diffusion, inverse folding and predictors. There is no common cross-model gradient, shared latent parameterization or validated differentiable interface between those models.

Offline source now includes descriptor-directed operation selection and sequence-seeded BindCraft feedback (five synthetic contract tests), but this update is not yet deployed or GPU qualified. The deployed default loop also falls short of the full intended optimizer: generators run at initialization, inverse-folding branches follow a configured list, and only candidates passing conservative prediction/physics gates enter later rounds. Missing independent predictors and physics currently prevent a scientifically qualified continuing frontier. Evaluation can decide *which candidates continue*, but the deployed controller does not diagnose a liability and choose a different gradient/diffusion operation dynamically. These distinctions must remain visible.

## Mathematical assessment of the original vision

1. **Gradient sequence optimization:** yes, inside unchanged BindCraft2 trajectory/sequence-optimization functions. Existing genuine local execution supports that scope. The first A10080GB trajectory now supplies real optimizer/loss/coordinate evidence; its original final filters rejected the design.
2. **Diffusion conformation generation:** authentic BoltzGen and RFdiffusion invocation code exists, but no cloud trained-model output has established this capability. BoltzProt is a separately hosted service, not installed NVIDIA weights.
3. **Inverse sequence design on generated backbones:** data transformation and separate model tasks exist. Actual local dual MPNN runs used the saved parent; new cloud-generated-parent evidence is pending.
4. **Reconstruction of modified complexes:** held-out AF2 and authentic ESM tasks are implemented. Cloud inference remains to be demonstrated. AF2 export now derives residue names from the predicted input sequence while preserving author numbering; it does not copy old residue identities into mutated predictions.
5. **Independent mathematical criteria:** measured contacts, clashes, SASA/interface area, target-aligned RMSD and descriptive liabilities are implemented. These are not free energies or calibrated binding probabilities. Rosetta is not available. Shared AF2 model families remain correlated.
6. **Evaluation changes the next operation:** currently partial. `select` gates the next frontier; the default next operation list is static. Liability-directed dispatch and verified structural/gradient feedback are unfinished.
7. **Iterative improvement and revalidation:** bounded discrete rounds exist, fresh predictions are required after mutations, and improvement is not guaranteed. Complete scientific multi-round validation is absent; missing independent-family/physics gates can legitimately stop the run.
8. **Prediction versus demonstrated function:** distinct in candidates/reports, with empty scientifically qualified finalists where evidence is missing. Original acceptance filters are preserved. Diagnostic follow-up from a rejected generator never changes its rejection outcome.
9. **Automatic fixed-budget control:** remote CPU orchestration, stage/candidate/round/wall limits, full-resource reservations, live elapsed estimates and cancellation exist. Actual bill enforcement is external; provider invoice is reported as unavailable until retrieved.
10. **Integrated platform or adapters:** an implemented shared discrete coordination layer over authentic model adapters, with meaningful validated identity/persistence/selection mechanisms. It is **not yet the complete scientifically qualified bidirectional molecular evolution system**.

True differentiable cross-model coupling would require compatible continuous sequence/coordinate representations, differentiable model interfaces and losses, gradient propagation through every chosen transformation, validated gradient/finite-difference checks, stable precision/memory behavior and a scientific benchmark against discrete baselines. Sampling/argmax, CLI boundaries and persisted candidate JSON currently break that gradient graph. No such joint-optimization claim is justified.
