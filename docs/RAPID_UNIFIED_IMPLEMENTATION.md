# RAPID unified campaigns — 24 October 2026

The complete directive is **not finished**. No Modal account is configured on the tested Mac, no immutable deployed RAPID image has been supplied, no cloud models have been downloaded, and no paid GPU/API operation has been launched. Scientific cloud qualification remains false.

## Implemented in this change

The portable controller now owns one durable campaign manifest, journal, stage graph, cancellation flag, candidate namespace and comparative report. It invokes the existing original engine supervisors; it does not substitute scientific models. BindCraft2 and BoltzGen generation can feed automatic ProteinMPNN and SolubleMPNN branches, fresh ESMFold2 Fast/full and held-out AF2 evaluation, shared coordinate/developability assessments, optional licensed Rosetta, and explicit Pareto selection. Identical sequences from different redesign models retain different immutable identities. Sequence-only descendants have a separately labelled reference backbone and no predicted coordinates or inherited confidence.

Model output bytes, sequences, context chains and residue maps are verified before candidate publication. Prediction drift is measured after target C-alpha alignment. Worst-sample limits and predictor-family dependence remain explicit. Fast/full ESM are one family. Original supplied structures conservatively count as AF2-conditioned. No biochemical affinity, inhibition, measured solubility or probability is inferred. Without a held-out physical assessment, finalists remain gated; geometry and sequence measurements still run without Rosetta.

The controller reserves each stage's full reviewed runtime estimate before dispatch, refuses unsupported representations, enforces runtime/candidate/round bounds, and stops subsequent stages on cancellation or insufficient allowance. Missing runtime/model inventory blocks a stage before allocating a GPU. Unknown claimed dispatches are never automatically retried. Portable SSH RPC supports unified validation/submission/status/cancellation and verified stage import; the existing Vast single-engine interface remains intact.

Modal now defines a CPU coordinator; specialized BindCraft2, BoltzGen, MPNN, ESM and AF2 GPU functions; a CPU Rosetta function; control, setup and explicitly approved CUDA numerical qualification functions. Runtime environments remain isolated. Scientific host memory and CPU reservations are explicit (default 64 GiB/2 CPUs per scientific stage). Engine-specific immutable images can be supplied. Modular sequential execution is the default; no measured warm-worker profile exists.

The CPU coordinator is the sole campaign metadata writer. Stage SQLite databases are disjoint. Research and model installation use separate named Volumes, with commit/reload at handoffs and a global provider writer lease across campaign/setup/qualification paths. Live progress and cancellation use a Modal Dict. Disk journals remain authoritative after the function's return value expires. The local journal, remote execution call IDs and request keys allow read-only reconnection without resubmission. A lost coordinator with an uncertain active stage stops for reconciliation; exact optimizer restart is not advertised.

Cloud Compute now contains **Modal — Serverless GPU** account, immutable image profile, deployment, model inventory/setup, bounded numerical GPU test, campaign preparation, workload approval, stage monitoring, cancellation, report and verified Research Library/viewer import controls. Official browser authentication writes its token to a private temporary SDK config and promotes it to macOS Keychain before deleting that file. Tokens and login output never enter project records. Existing official SDK credentials are detected without printing their values.
